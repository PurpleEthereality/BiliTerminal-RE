v1 声称「7 套主题都没有任何弹窗相关声明，弹窗层从未接入主题系统」。这句话不成立 —— themes.xml 里 7 套主题都明明白白写了 colorSurface（:15,55,104,219,334,449,564,683）， XML 侧也有 71 处 ?attr/colorSurface、?attr/colorPrimary 在用。 主题系统是真实、完备、正在工作的。v1 把「半接入」误判成了「未接入」，方向也就跟着偏了。

0 · 精确根因：不是「没接入」，是差三个属性

重新逐项核对后，缺口非常具体 —— 全仓 grep，下面三个属性在 app/src/main/res 全域 0 命中：

✗alertDialogTheme　/ android:alertDialogTheme　/ dialogTheme　→ 全仓 0 命中
✗colorOnSurface　→ 全仓 0 命中
✗colorError　→ 全仓 0 命中

对照组：colorOnPrimary 有 15 处（每套主题 1 处，外加 Light 变体）， 且全部指向同一个 @color/text_on_primary —— 说明这套主题是「按 Material 属性逐个补齐」的风格， 只是弹窗专属的那三个从没被补上。

缺的属性Material 回退到什么用户看到的现象
alertDialogTheme 回退到 Theme.MaterialComponents.NoActionBar 自带的默认 alert overlay，而不是本主题的颜色 overlay 弹窗整体走 Material 默认配色，只有 colorAccent 是唯一跟着本主题走的
colorOnSurface Material 默认近白色 「白字」。注意：本主题其实设了 android:colorForeground=@color/terminal_textwhite(#EBE0E2)， 但 Material 的正文文字不读 colorForeground，读 colorOnSurface —— 所以设了也没用
colorError Material 默认红 「删除评论 / 删除账号」这类破坏性按钮没有危险语义，与「取消」同色
「粉色按钮」的确切来源：AppCompat 的 AlertDialog 里，setPositiveButton / setNegativeButton 的文字色由 colorAccent 决定。 7 套主题全都设了 colorAccent（Theme.BiliClient 与 Theme.ClassicTerminal 都是 #FF6699），所以按钮色确实跟随了主题 —— 只是恰好跟到了一个刺眼的荧光粉。这恰好印证了 v1 的反面：不是没接入，是接入了、但只接入了最不该接入的那一项。
前序修复其实已经摸到了这个方向。 themes.xml:681-682 留着一条注释：
<!-- 其余 6 套主题都有 colorSurface / android:colorBackground，默认主题此前缺这 4 项，
     Material 控件（卡片、弹窗、选中态）会回退到 MaterialComponents 默认值，与本主题不符 -->
这条注释明确点了「卡片、弹窗、选中态」，并已给 Theme.ClassicTerminal 补上了 colorSurface=@color/terminal_surface、android:colorBackground、 colorControlActivated/Normal/Highlight。 本次要做的就是把这条修复推完：底色那一半已经补上（所以底色偏黑是对的）， 文字与按钮那两半还没补。这属于前序未覆盖的剩余环节，不是回归，也不是「没有主题系统」。

2 · 修复思路：补属性，不改调用点

核心结论：17 个弹窗调用点一行代码都不用改。
只要在 themes.xml 的 7 套主题里把 alertDialogTheme 指到各自的 overlay， 并在 overlay 里定义 colorSurface / colorOnSurface / colorError， AlertDialog.Builder 的所有实例（android.app 与 androidx.appcompat.app 两种 import）全部同时生效。 这是「在主题层一次性收敛」，而不是「改 17 处」。

落地形态（每套主题一份 overlay，共 7 份 + Light）

7 套主题各自themes.xml 加 1 行引用
新增ThemeOverlay.<X>.Dialog
overlay 内定义3 个属性
调用点改动0 行

Kotlin 侧 ColorScheme.kt 不需要动：它的 36 个字段里本就没有「弹窗专属色」的概念， 弹窗色应当由 XML 主题属性表达，这才符合本仓既有的「配色走主题属性」惯例。
